## From test strategy to defensible quality evidence

**I approach software quality as an end-to-end engineering discipline, not simply a collection of automated scripts.** From requirements and risk analysis to test strategy, coverage design, implementation, execution, defect investigation, traceability, reporting, and test closure, I focus on making quality decisions explicit and their outcomes verifiable.

My experience includes software testing in the **banking domain**, alongside a technical focus on **Java-based test automation**. I work with **Selenium WebDriver** for UI testing, **REST Assured** for API verification, and **TestNG** to structure automated execution. The engineering objective is consistent: maintainable tests, meaningful assertions, reliable feedback, and evidence that other engineers can reproduce.

## Current engineering priorities

- **UI automation:** robust browser tests, reusable abstractions, test data, and relevant assertions.
- **API and integration testing:** positive and negative scenarios, response validation, and cross-layer coverage.
- **CI/CD quality feedback:** repeatable execution, pipeline integration, interpretable reports, and failure diagnosis.
- **Test process management:** risk-based prioritisation, traceability, defect management, and completion criteria.

Beyond delivery, I extend these methods into **vocational education**, helping others build not just tool proficiency, but sound testing judgment and lasting technical independence.
